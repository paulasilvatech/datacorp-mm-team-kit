## What a DDM is

A **DDM (Data Definition Module)** is the file that describes the schema of an Adabas database—equivalent to a SQL `CREATE TABLE`. Each DDM lists the fields (with type, size, and attributes such as descriptor or multiple value) of an Adabas file (FNR).

**Why it matters:** without reading the DDM, you do not know which fields exist, what types they have, or which structures (`MU`, `PE`) will need to become child tables in PostgreSQL. Field names in `.NSN` programs are abbreviations that only make sense when cross-referenced with the DDM.

**How this applies to SIFAP:** the `CALCBENF.NSN` program references fields such as `BN-AMT-INCOME-PC` and `PS-AMT-MAX`. To understand what each field represents, consult the `BENEFICIARY` and `SOCIAL-PROGRAM` DDMs.

## How to read a DDM

The `.ddm` files in this directory are **listings** generated by the SYSDDM `LISTDDM` utility—that is, machine output, not editable source. The main table always has the same eight columns:

```text
 T L DB Name                     F Leng  S D Remark
 - - -- ------------------------ - ----  - - ---------------------------
   1 AB NUM-CPF                  A   11    U UNFORMATTED CPF
 P 1 DA GRP-DEPEND                        (1:10) PERIODIC GROUP
 S   S2 SUPER-UF-STAT             A    3    S
        /* BG(1-2), CE(1-1)
```

| Column | Meaning | Possible values |
|---|---|---|
| **T** | Entry type | *(blank)* = elementary field · `G` = group · `M` = multiple-value (`MU`) · `P` = periodic group (`PE`) · `S` = derived descriptor |
| **L** | Level | `1` = root field · `2` = field within a group or PE. Derived descriptors have no level |
| **DB** | *Short name* | **2-byte** physical name in the FDT. It is the only name the Adabas file actually knows |
| **Name** | Long name | Exists only in the DDM. It is the name Natural programs use in `VIEW OF` declarations |
| **F** | Format | `A` = alphanumeric · `N` = *unpacked* numeric (1 byte per digit) · `P` = *packed decimal* (2 digits per byte) |
| **Leng** | Length | Bytes, or `digits,decimals` for fields with decimal places—**always with a comma** (`9,2`, never `9.2`) |
| **S** | *Storage option* | `N` = *null suppression* (an empty field occupies no space and is not added to the index) · `F` = *fixed storage* (uncompressed, typical for 1-byte indicators) |
| **D** | Descriptor | `D` = descriptor · `U` = unique descriptor · `S` = superdescriptor · `H` = hyperdescriptor · `P` = phonetic descriptor |
| **Remark** | Comment | Value domain, sentinels, and field addition date. `MU`/`PE` occurrences appear here as `(1:10)` |

Lines beginning with `/*` immediately below a derived descriptor list **the fields that compose it**. For example, `/* BG(1-2), CE(1-1)` means "bytes 1–2 of `BG` concatenated with byte 1 of `CE`."

> [!IMPORTANT]
> **`FIND ... WITH <field>` and `READ ... BY <field>` are valid only if the field has a value in column `D`.** Searching by a non-indexed field is an Adabas runtime error, not a compilation error—the program "works" until it runs. This is the first check when reading a `.NSN` program.

### DDM × FDT

| | DDM (`.ddm`) | FDT (`FDT-150-BENEFICIARY.txt`) |
|---|---|---|
| What it is | **Logical** view used by Natural | **Physical** layout of the database file |
| Names | Long names (`NUM-CPF`) | *Short names* only (`AB`) |
| Generated by | `LISTDDM` (SYSDDM) | `ADAREP` / `ADACMP` |
| Includes data volume? | Estimates in the footer | Yes: `TOP-ISN`, `MAXISN`, compression ratio, extents, unload estimate |

A real migration team receives **both**. The DDM explains what the fields mean; the FDT shows how much data exists and how long it will take to extract.

### Known pitfalls in this corpus

- **Alphanumeric fields used as numeric values.** Several fields are `A` in the DDM but appear as `N` in programs, including in arithmetic and as array indexes. An old record containing spaces in an `A` field causes an error when moved to `N`.
- **Sentinels instead of null.** `0` meaning "no deadline," `00000000000` as a placeholder CPF, and `99999999` as an unknown date. None of them is `NULL`.
- **Orphan fields.** Some fields have existed in the schema for decades, but none of the 15 programs reads or writes them. Verify before assuming that a column contains data.
- **Domains documented in the remark may be outdated.** The remark describes the domain *when the field was created*, not necessarily what is stored today.

## How to use these files during Stage 1

- [ ] **Open the DDMs relevant to the selected feature.** Not all four are always necessary.
- [ ] **Read the "How to read a DDM" section above** before cross-referencing a DDM with a program—the comparison is meaningless without columns `T`/`S`/`D`.
- [ ] **Identify `MU` and `PE` fields** (column `T` = `M` or `P`). These become child tables in PostgreSQL.
- [ ] **Check column `D` before accepting a `FIND`/`READ BY`.** If the field is not a descriptor, the access is illegal in Adabas.
- [ ] **Compare every `VIEW OF` with the corresponding DDM.** Name, format, and length must match.
- [ ] **Record the mapping** in [`dependency-map.md`](../../dependency-map.md) (Program → DDM edges section).
- [ ] **Contribute terms** to [`glossary.md`](../../glossary.md)—field names often reveal domain abbreviations.

> [!WARNING]
> These files are read-only reference material. Do not edit the DDMs.
